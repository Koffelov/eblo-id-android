# eblo.id — неофициальный Android-клиент

> **Неофициальное приложение.** Не связано с [eblo.id](https://eblo.id) и его авторами.
> Это оболочка, которая показывает настоящий сайт https://eblo.id в окне приложения.

Скачать: **[последний релиз](https://github.com/Koffelov/eblo-id-android/releases/latest)** → файл `eblo-id-<версия>.apk`.

## Почему оболочка, а не «нативный» клиент

Что было выяснено при исследовании сайта:

| Что | Есть ли | Подробности |
|---|---|---|
| Публичный API | только чтение | `GET /api/public/post/<код>`, `GET /api/public/posts?codes=a,b`, `GET /api/public/upload-limits` (описаны на `/uploaders`) |
| API загрузки файлов | да, по личному ключу | ключ выдаётся на `/uploaders` после входа; предназначен для ShareX/расширений, а не для ленты, профилей и комментариев |
| API ленты, профилей, комментариев, лайков, входа | нет документированного | сайт использует внутренние `/api/feed`, `/api/profile/…` с CSRF-токеном и Cloudflare Turnstile — они могут измениться в любой момент |
| Вход | Twitch OAuth | `/login/twitch` → `id.twitch.tv` → `https://eblo.id/auth/twitch/callback`; адрес возврата закреплён за доменом сайта |
| Защита | Cloudflare Turnstile | включается при подозрительных действиях, работает только в настоящем браузерном движке |
| Digital Asset Links | нет | `https://eblo.id/.well-known/assetlinks.json` → 404, поэтому полноэкранный TWA без адресной строки невозможен |

Поэтому приложение — тонкая нативная оболочка на системном Android WebView (Java, **без сторонних библиотек**, APK ≈ десятки КБ).
Внешний вид и поведение — это сам сайт с его мобильной вёрсткой (нижняя панель «Лента / Видосы / + / Уведомления / Войти»).

### Как решены ограничения WebView

- **Вход.** Весь Twitch OAuth проходит внутри того же WebView: Twitch возвращает на `eblo.id/auth/twitch/callback`, cookie сессии сохраняется в хранилище приложения и переживает перезапуск. Внешний браузер для входа не используется — его cookies в WebView не попадают. Страницы `*.twitch.tv` открываются внутри приложения только во время входа; обычные ссылки на Twitch открываются в приложении Twitch/браузере.
- **Вложения.** `<input type="file">` сайта открывает системный выбор файлов Android (с множественным выбором, если сайт его разрешает). Типы и лимиты проверяет сам сайт (сейчас: изображения, видео, аудио, архивы, документы; до 200 МБ, до 10 файлов в альбоме).
- **Клавиатура.** Окно сжимается под клавиатуру (edge-to-edge, отступы от системных панелей и IME), поле ввода не перекрывается.
- **«Назад».** Возврат по истории сайта, выход из полноэкранного видео; на Android 13+ — через predictive back.
- **Внешние ссылки.** Всё, что не `eblo.id`, открывается в соответствующем приложении (браузер, Telegram, YouTube, почта). `intent://`-ссылки обрабатываются с fallback-адресом.
- **Нет интернета.** Экран «Нет подключения к интернету» с кнопкой «Повторить»; при появлении сети страница перезагружается сама.
- **Прочее.** Полноэкранное видео, скачивание файлов в «Загрузки» (Android 10+; на старых — через браузер), открытие ссылок `https://eblo.id/...` из других приложений (после ручного включения, см. ниже).

## Установка на Android

1. На телефоне откройте [Releases](https://github.com/Koffelov/eblo-id-android/releases/latest) (репозиторий приватный — нужно войти в GitHub в браузере телефона) и скачайте `eblo-id-<версия>.apk`.
2. Откройте скачанный файл. Если Android спросит — разрешите «Установка неизвестных приложений» для браузера/файлового менеджера.
3. Запустите «eblo.id (неоф.)», прочтите уведомление, нажмите «Войти» на сайте и авторизуйтесь через Twitch.

Чтобы ссылки `https://eblo.id/...` из Telegram и т.п. открывались в приложении: *Настройки → Приложения → eblo.id (неоф.) → Открывать по умолчанию → Добавить ссылку → eblo.id*.

## Обновления

Каждая новая версия публикуется в [Releases](https://github.com/Koffelov/eblo-id-android/releases). Скачайте новый APK и установите поверх — все релизы подписаны одним постоянным ключом, поэтому данные и вход сохраняются. Чтобы получать уведомления: на странице репозитория *Watch → Custom → Releases*.

## Сборка (только GitHub Actions)

Локально ничего ставить не нужно: Android SDK и JDK есть на раннерах GitHub.
Workflow: [`.github/workflows/android.yml`](.github/workflows/android.yml).

| Событие | Что происходит |
|---|---|
| push в `main`, pull request | debug-APK (артефакт, только для тестов, ставится отдельным приложением «eblo.id DEBUG») и подписанный release-APK (артефакт) |
| тег `v*` (например `v1.1.0`) | то же + GitHub Release с подписанным APK |
| Actions → Android → *Run workflow* | ручная сборка; галочка «Опубликовать GitHub Release» выпускает версию `1.0.<номер запуска>` |

`versionCode` = 100 + номер запуска, поэтому каждая следующая сборка ставится поверх предыдущей.

### Подпись

Release подписывается постоянным ключом PKCS#12 из секретов репозитория:
`ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`.
Ключ и пароли в репозиторий не коммитятся. Workflow сверяет SHA-256 сертификата
(`e203df76294e0157675b63cae0fcddff8c7fb68a53c382bd0c5b62db916eb295`) и падает, если APK подписан чем-то другим;
без секретов релиз не публикуется.

Оригинал ключа хранится у владельца вне репозитория. **Сделайте его резервную копию** — без него
обновления поверх установленной версии станут невозможны (придётся удалять приложение и входить заново).

## Известные ограничения

- Приложение показывает сайт как есть: функции, которых нет на сайте, в нём не появятся; если сайт изменится или будет недоступен — изменится и приложение.
- Нет push-уведомлений: у сайта нет для этого API; уведомления видны внутри сайта.
- Вход через Twitch в WebView: если Twitch потребует вход по passkey/ключу безопасности, используйте пароль + код 2FA. Если Twitch когда-нибудь запретит вход во встроенных браузерах, войти в приложении не получится — перенести сессию из внешнего браузера нельзя.
- Проверка Cloudflare Turnstile может появляться так же, как в браузере.
- Не TWA: у eblo.id нет `assetlinks.json`, поэтому ссылки eblo.id не открываются в приложении автоматически (только после ручного включения, см. выше).
- Скачивание файлов на Android 7–9 передаётся браузеру.
